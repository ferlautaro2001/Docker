## Eliminar un volumen

Los volúmenes ocupan espacio en disco, así que cuando ya no los necesito, es buena práctica eliminarlos. Pero atención: `docker volume rm` solo funciona si **ningún contenedor** (en ejecución o detenido) está usando el volumen. Si algún contenedor lo tiene montado, Docker bloquea la eliminación para evitar pérdida de datos.

### Ver todos los contenedores (incluso los detenidos)

Antes de eliminar el volumen, necesito asegurarme de que ningún contenedor lo esté usando. `docker ps -a` muestra todos los contenedores, incluso los que ya no están corriendo:

```bash
docker ps -a
```

**Salida esperada:**
```
CONTAINER ID   IMAGE          COMMAND                  CREATED          STATUS                        PORTS     NAMES
7a8b9c0d1e2f   ghost:latest   "docker-entrypoint.s…"   10 minutes ago   Up 10 minutes                 0.0.0.0:3001->2368/tcp   ghost_container
f1a2b3c4d5e6   ghost:latest   "docker-entrypoint.s…"   1 hour ago       Exited (0) 50 minutes ago               old_ghost
```

> 📋 **Nota:** `STATUS` me dice si el contenedor está `Up` (en ejecución) o `Exited` (detenido). Necesito detener y eliminar **todos** los contenedores que usen el volumen antes de eliminarlo.

---

### Detener y eliminar el contenedor Ghost

Primero detengo el contenedor que está corriendo:

```bash
docker stop 7a8b9c0d1e2f
```

**Salida esperada:**
```
7a8b9c0d1e2f
```

Luego elimino el contenedor:

```bash
docker rm 7a8b9c0d1e2f
```

**Salida esperada:**
```
7a8b9c0d1e2f
```

> 💡 **Tip:** si tengo varios contenedores detenidos que ya no necesito, puedo limpiarlos todos con `docker container prune`.

---

### Eliminar el volumen

Ahora que ningún contenedor usa `ghost-vol`, puedo eliminarlo:

```bash
docker volume rm ghost-vol
```

**Salida esperada:**
```
ghost-vol
```

> 🗑️ **Nota:** si veo un error como `volume ghost-vol is in use`, significa que algún contenedor (ejecutando o detenido) todavía lo tiene montado. Uso `docker ps -a` para encontrarlo y eliminarlo.

---

### Comportamiento automático de Docker

Si después de eliminar el volumen corro esto:

```bash
docker run -d -e NODE_ENV=development -e url=http://localhost:3001 -p 3001:2368 -v ghost-vol:/var/lib/ghost ghost:latest
```

Docker **no** da error. En cambio, **crea el volumen automáticamente** porque `-v ghost-vol:/var/lib/ghost` le dice que monte el volumen `ghost-vol`, y si no existe, lo crea en el momento.

```bash
docker volume ls
```

**Salida esperada (el volumen volvió a aparecer):**
```
DRIVER    VOLUME NAME
local     ghost-vol
```

> 🧠 **Comportamiento clave:** `-v nombre_volumen:ruta` en `docker run` **siempre** monta un volumen. Si no existe, lo crea automáticamente. Esto es útil para no tener que correr `docker volume create` antes, pero también puede causar confusión si no me doy cuenta de que se creó uno nuevo.


**Pasos para la lección (resumen):**
1. `docker ps -a` — veo todos los contenedores, incluso detenidos.
2. `docker stop <ID>` — detengo el contenedor Ghost.
3. `docker rm <ID>` — elimino el contenedor Ghost.
4. `docker volume rm ghost-vol` — elimino el volumen.
5. Si corro `docker run ... -v ghost-vol:/var/lib/ghost ...` sin el volumen, Docker lo crea automáticamente.
