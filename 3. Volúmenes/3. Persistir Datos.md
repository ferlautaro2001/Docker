## Persistiendo datos con volúmenes

Ahora voy a comprobar que el volumen realmente funciona. Si detengo y elimino el contenedor actual, y luego arranco uno nuevo con el mismo volumen montado, el blog debería seguir teniendo mi post. Esto demostraría que los datos viven en el volumen, no en el contenedor.

### Obtener el ID del contenedor

Primero necesito saber qué contenedor está corriendo:

```bash
docker ps
```

**Salida esperada:**
```
CONTAINER ID   IMAGE          COMMAND                  CREATED         STATUS         PORTS                    NAMES
7a8b9c0d1e2f   ghost:latest   "docker-entrypoint.s…"   5 minutes ago   Up 5 minutes   0.0.0.0:3001->2368/tcp   quirky_fermat
```

> **Tip:** copio el `CONTAINER ID` (o el nombre) para usarlo en el siguiente paso.

---

### Detener y eliminar el contenedor

```bash
docker stop 7a8b9c0d1e2f
docker rm 7a8b9c0d1e2f
```

**Salida esperada:**
```
7a8b9c0d1e2f
7a8b9c0d1e2f
```

> ⚠️ **Nota:** `docker rm` solo funciona si el contenedor ya está detenido. Si intento eliminar uno en ejecución, Docker me pide que lo detenga primero o use `-f` para forzar.

---

### Crear un nuevo contenedor con el mismo volumen

Ahora arranco un contenedor nuevo, usando la misma imagen y el mismo volumen que antes, pero agregando variables de entorno que Ghost necesita para correr en modo desarrollo y con la URL correcta:

```bash
docker run -d \
  -e NODE_ENV=development \
  -e url=http://localhost:3001 \
  -p 3001:2368 \
  -v ghost-vol:/var/lib/ghost \
  ghost:latest
```

**Salida esperada (ID del nuevo contenedor):**
```
f1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1
```

> 🧠 **¿Qué hacen estas variables?**
> - `NODE_ENV=development` — le dice a Ghost que corra en modo desarrollo (útil para debugging local).
> - `url=http://localhost:3001` — le dice a Ghost que la URL pública de mi sitio es esa. Sin esto, algunos enlaces y redirecciones pueden fallar.

---

### Verificar que los datos persisten

Ahora abro http://localhost:3001/ en mi navegador. Debería ver el mismo blog que tenía antes, con el post "I Love Docker" publicado. Si veo el post, significa que el volumen funcionó correctamente: los datos sobrevivieron al contenedor original.

---

### ¿Qué pasa si la página está vacía o no tiene el post?

Significaría que:
1. El volumen no se montó correctamente en el nuevo contenedor.
2. O el volumen no contenía los datos (tal vez no se montó bien la primera vez).

```bash
# Para verificar que el volumen existe y está montado
docker volume ls
docker volume inspect ghost-vol
```

**Volumen que debería aparecer:**
```
DRIVER    VOLUME NAME
local     ghost-vol
```

> 💡 **Conclusión:** los volúmenes son la forma de persistir datos en Docker. Sin ellos, cada contenedor nuevo sería un borrón y cuenta nueva.


**Pasos para la lección (resumen):**
1. `docker ps` — obtengo el ID del contenedor actual.
2. `docker stop <ID>` — lo detengo.
3. `docker rm <ID>` — lo elimino.
4. `docker run -d -e NODE_ENV=development -e url=http://localhost:3001 -p 3001:2368 -v ghost-vol:/var/lib/ghost ghost` — arranco uno nuevo con el mismo volumen.
5. Abro `http://localhost:3001/` y confirmo que el post sigue ahí.
