
## `docker volume create`

Los volúmenes son la forma que tiene Docker de persistir datos más allá del ciclo de vida de un contenedor. Cuando creo un contenedor desde una imagen, el sistema de archivos es efímero: si elimino el contenedor, se pierden todos los cambios. Pero si monto un volumen en una ruta específica dentro del contenedor, todos los archivos que se escriban en esa ruta se guardan en el volumen, que vive fuera del contenedor y puede sobrevivir a su eliminación.

En esta lección voy a crear un volumen para Ghost (un blog), así los posts y configuraciones se preservan aunque el contenedor se detenga o elimine.

### Crear el volumen

**Ejemplo de comando:**
```bash
docker volume create ghost-vol
```

**Salida esperada (devuelve el nombre del volumen):**
```
ghost-vol
```

---

## `docker volume ls`

Este comando lista todos los volúmenes que tengo en mi sistema Docker. Es útil para verificar que se creó correctamente y que está disponible para montar en contenedores.

**Ejemplo de comando:**
```bash
docker volume ls
```

**Salida esperada:**
```
DRIVER    VOLUME NAME
local     ghost-vol
```

> 📦 **Nota:** el driver `local` es el predeterminado. En producción podés usar otros drivers para almacenamiento en red (NFS, S3, etc.).

---

## `docker volume inspect`

`docker volume inspect` me muestra información detallada de un volumen específico, como su ubicación física en el sistema de archivos del host, el driver que usa, las opciones de montaje, y metadatos. Esto es útil para saber dónde están realmente los archivos persistentes si necesito acceder a ellos directamente desde el host.

**Ejemplo de comando:**
```bash
docker volume inspect ghost-vol
```

**Salida esperada:**
```json
[
    {
        "CreatedAt": "2024-01-15T10:30:00Z",
        "Driver": "local",
        "Labels": {},
        "Mountpoint": "/var/lib/docker/volumes/ghost-vol/_data",
        "Name": "ghost-vol",
        "Options": {},
        "Scope": "local"
    }
]
```

> 📂 **Tip:** `Mountpoint` es la ubicación real en mi sistema donde Docker guarda los archivos de este volumen. Si necesito copiar archivos manualmente al volumen, los puedo poner ahí directamente (aunque siempre es mejor hacerlo desde el contenedor o usando `docker cp`).

---

### ¿Por qué necesito volúmenes?

Sin volúmenes, si hago esto:
1. Arranco un contenedor.
2. Instalo algo o creo archivos dentro.
3. Detengo y elimino el contenedor.

Los cambios se pierden porque el contenedor arranca siempre desde la imagen original.

Con volúmenes, los datos persisten entre reinicios y contenedores distintos. Esto es fundamental para bases de datos, blogs, archivos subidos por usuarios y cualquier cosa que deba sobrevivir al contenedor.


**Pasos para la lección (resumen):**
1. `docker volume create ghost-vol` — creo el volumen.
2. `docker volume ls` — verifico que existe.
3. `docker volume inspect ghost-vol` — veo sus detalles.
