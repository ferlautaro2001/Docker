## `docker exec`

`docker exec` me permite ejecutar comandos **dentro** de un contenedor que ya está corriendo. Es como tener una terminal remota dentro del contenedor, sin necesidad de abrir una shell interactiva. Esto es muy útil para depurar, inspeccionar archivos, o ejecutar tareas administrativas sin interrumpir el proceso principal.

La sintaxis básica es: `docker exec <ID> <comando>`.

### Ver los contenedores en ejecución

Primero veo qué contenedores tengo corriendo:

```bash
docker ps
```

**Salida esperada:**
```
CONTAINER ID   IMAGE                           COMMAND                  CREATED         STATUS         PORTS                  NAMES
2f3a4b5c6d7e   docker/getting-started:latest   "/docker-entrypoint.…"   2 seconds ago   Up 1 second    0.0.0.0:8965->80/tcp   naughty_galileo
```

---

### Arrancar el contenedor de getting-started

```bash
docker run -d -p 8965:80 docker/getting-started
```

**Salida esperada:**
```
2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f
```

---

### Verificar que el contenedor está corriendo

```bash
docker ps
```

**Salida esperada:**
```
CONTAINER ID   IMAGE                           COMMAND                  CREATED         STATUS         PORTS                  NAMES
2f3a4b5c6d7e   docker/getting-started:latest   "/docker-entrypoint.…"   2 seconds ago   Up 1 second    0.0.0.0:8965->80/tcp   naughty_galileo
```

---

### Ejecutar `ls` dentro del contenedor

```bash
docker exec 2f3a4b5c6d7e ls
```

**Salida esperada:**
```
bin
boot
dev
etc
home
lib
lib64
media
mnt
opt
proc
root
run
sbin
srv
sys
tmp
usr
var
```

> 📂 **Nota:** esto lista el directorio raíz (`/`) del contenedor, que es su propio sistema de archivos aislado.

---

### Crear un archivo dentro del contenedor

```bash
docker exec 2f3a4b5c6d7e touch hacker.log
```

**Salida esperada:** no hay salida si el comando funciona bien.

---

### Verificar que el archivo fue creado

```bash
docker exec 2f3a4b5c6d7e ls
```

**Salida esperada (debería incluir hacker.log):**
```
bin
boot
dev
etc
hacker.log
home
lib
...
```

> 🧠 **Conclusión:** `docker exec` me permite ejecutar comandos dentro del contenedor como si estuviera en el sistema de archivos del contenedor. En este ejemplo, creé `hacker.log` en el directorio raíz del contenedor.

---

### ¿Para qué sirve `docker exec` en la práctica?

- Depurar errores dentro de un contenedor.
- Ver logs de aplicaciones que no están configuradas para enviar logs a stdout.
- Correr migraciones de base de datos.
- Inspeccionar archivos generados por la aplicación.
- Ejecutar scripts de mantenimiento o limpieza.

> ⚠️ **Advertencia:** `docker exec` es útil para troubleshooting, pero no debería ser parte del flujo normal de ejecución de la aplicación. La configuración y el estado de un contenedor deberían definirse en la imagen o manejarse mediante volúmenes.


**Pasos para la lección (resumen):**
1. `docker ps` — veo los contenedores activos.
2. `docker run -d -p 8965:80 docker/getting-started` — arranco el contenedor.
3. `docker ps` — confirmo que está corriendo.
4. `docker exec <ID> ls` — listo archivos dentro del contenedor.
5. `docker exec <ID> touch hacker.log` — creo un archivo.
6. `docker exec <ID> ls` — verifico que el archivo fue creado.
