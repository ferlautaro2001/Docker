## `docker exec -it` (shell interactiva)

`docker exec -it` me permite abrir una **shell interactiva** dentro de un contenedor en ejecución. Es como `ssh` a un servidor remoto: puedo navegar directorios, modificar archivos, instalar paquetes y ejecutar comandos como si estuviera dentro del sistema de archivos del contenedor.

Los flags:
- `-i` (*interactive*) — mantiene abierta la entrada estándar (STDIN), permitiendo enviar comandos.
- `-t` (*tty*) — asigna una pseudo-terminal, necesaria para usar shells como `/bin/sh` o `/bin/bash`.

---

### Abrir una shell dentro del contenedor

```bash
docker exec -it 2f3a4b5c6d7e /bin/sh
```

**Salida esperada (el prompt cambia a la shell del contenedor):**
```
# 
```

> 💡 **Nota:** el prompt `#` indica que soy `root` dentro del contenedor. Desde acá, cualquier comando que ejecute se ejecuta **dentro** del contenedor, no en mi host.

---

### Navegar al directorio donde sirve Nginx

```bash
# cd /usr/share/nginx/html/
```

> 📂 **¿Por qué esta ruta?** Es el directorio raíz donde Nginx sirve archivos por defecto en la imagen oficial de Nginx.

---

### Ver el contenido de la página

```bash
# ls
```

**Salida esperada:**
```
50x.html  index.html
```

> 📄 **Nota:** `index.html` es el archivo que se sirve cuando visito http://localhost:8965.

---

### Ver la página en el navegador

Abro `http://localhost:8965` en mi navegador. Debería ver la página de inicio de tutorial de Docker.

---

### Ingresar al directorio `tutorial`

```bash
# cd tutorial
```

**Salida esperada:** no hay salida, pero el prompt cambia a `/usr/share/nginx/html/tutorial`.

---

### "Hackear" el sitio

```bash
# echo "I hacked you!" > index.html
```

> 🖋️ **Nota:** este comando sobreescribe el archivo `index.html` con el texto "I hacked you!".

---

### Verificar el cambio

Ahora refresco `http://localhost:8965` en mi navegador. La página debería mostrar:

```
I hacked you!
```

> 🚀 **Conclusión:** pude modificar el contenido de la página web en vivo porque Nginx sirve archivos desde el directorio donde hice el cambio. El cambio es temporal (vive solo mientras el contenedor esté activo), pero demuestra cómo interactuar con el sistema de archivos del contenedor.

---

### Salir de la shell

```bash
# exit
```

**Salida esperada:** el prompt vuelve a mi terminal host.

---

### ¿Para qué sirve una shell interactiva en producción?

- Depurar errores de configuración.
- Ejecutar scripts de mantenimiento complejos.
- Inspeccionar archivos de log.
- Probar cambios rápidos (aunque no es recomendable en producción sin un proceso formal de deployment).


**Pasos para la lección (resumen):**
1. `docker exec -it <ID> /bin/sh` — abro una shell dentro del contenedor.
2. `cd /usr/share/nginx/html/` — voy al directorio de Nginx.
3. Verifico `http://localhost:8965` — muestra el tutorial.
4. `cd tutorial` — entro a la carpeta del tutorial.
5. `echo "I hacked you!" > index.html` — sobreescribo el archivo.
6. Refresco la página en el navegador — veo el mensaje hackeado.
7. `exit` — salgo de la shell.
