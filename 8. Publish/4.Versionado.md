## Tags y versionado de imágenes

Los **tags** en Docker son etiquetas que identifican versiones específicas de una imagen. Funcionan como los tags en Git: me permiten versionar mi imagen y mantener distintas versiones disponibles. Por convención, `latest` se usa para la versión más reciente, pero también es común usar tags semánticos como `0.1.0`, `0.2.0`, etc.

---

### 1. Actualizar el código del servidor

Modifico `main.go`, cambiando el mensaje HTML:

```go
const page = `<html>
<head></head>
<body>
	<p> Hi Docker, I pushed a new version. </p>
</body>
</html>
```

> 📝 **Nota:** el nuevo mensaje es "Hi Docker, I pushed a new version."

---

### 2. Recompilar el binario para Linux

```bash
GOOS=linux GOARCH=amd64 go build -o goserver
```

---

### 3. Construir la nueva imagen con un tag de versión

```bash
docker build . -t tu-usuario/goserver:0.2.0
```

**Salida esperada:**
```
[+] Building 0.3s (6/6) FINISHED
 => [1/2] FROM docker.io/library/debian:stable-slim
 => [2/2] COPY goserver /bin/goserver
 => exporting to image
 => => naming to docker.io/tu-usuario/goserver:0.2.0
```

> 📋 **Nota:** `0.2.0` es el nuevo tag. La imagen anterior (con `latest`) sigue existiendo; esta es una versión nueva.

---

### 4. Ejecutar el nuevo contenedor

```bash
docker run -p 8991:8991 tu-usuario/goserver:0.2.0
```

**Salida esperada:**
```
server started on 8991
```

---

### 5. Verificar en el navegador

Abro `http://localhost:8991/` en mi navegador. Debería ver el mensaje actualizado:

```
Hi Docker, I pushed a new version.
```

---

### 6. Subir la nueva imagen a Docker Hub

```bash
docker push tu-usuario/goserver:0.2.0
```

**Salida esperada:**
```
The push refers to repository [docker.io/tu-usuario/goserver]
2f3a4b5c6d7e: Pushed 
3a4b5c6d7e8f: Pushed 
0.2.0: digest: sha256:2f3a4b5c6d7e... size: 1234
```

> 📤 **Nota:** especifico el tag `0.2.0` para subir solo esa versión.

---

### 7. Verificar en Docker Hub

Abro mi perfil en Docker Hub: https://hub.docker.com/u/tu-usuario

**Debería ver el repositorio `goserver` con dos tags:**
- `latest` (versión anterior)
- `0.2.0` (nueva versión)

---

### 8. Detener y eliminar el contenedor

```bash
docker stop <ID>
docker rm <ID>
```

**Salida esperada:**
```
<ID>
<ID>
```

---

### 9. Eliminar las imágenes locales

```bash
docker image rm tu-usuario/goserver:latest
docker image rm tu-usuario/goserver:0.2.0
```

**Salida esperada:**
```
Untagged: tu-usuario/goserver:latest
Untagged: tu-usuario/goserver:0.2.0
Deleted: sha256:2f3a4b5c6d7e...
```

---

### 10. Descargar solo la nueva versión desde Docker Hub

```bash
docker pull tu-usuario/goserver:0.2.0
```

**Salida esperada:**
```
0.2.0: Pulling from tu-usuario/goserver
2f3a4b5c6d7e: Pull complete 
3a4b5c6d7e8f: Pull complete 
Digest: sha256:2f3a4b5c6d7e...
Status: Downloaded newer image for tu-usuario/goserver:0.2.0
docker.io/tu-usuario/goserver:0.2.0
```

---

### 11. Ejecutar la imagen descargada

```bash
docker run -p 8991:8991 tu-usuario/goserver:0.2.0
```

**Salida esperada:**
```
server started on 8991
```

> ✅ **¡Funciona!** La versión `0.2.0` se descargó y ejecuta correctamente.

---

### Comparación de versiones

| Tag | Mensaje | Estado |
|-----|---------|--------|
| `latest` | "Hello from Docker! I'm a Go server." | Versión anterior |
| `0.2.0` | "Hi Docker, I pushed a new version." | Versión nueva |

> 🧠 **Conclusión:** los tags me permiten tener múltiples versiones de la misma imagen en el registro. Puedo actualizar `latest` a la nueva versión si quiero que sea la predeterminada, pero manteniendo las versiones anteriores para rollback o compatibilidad.

**Pasos para la lección (resumen):**
1. Actualizo `main.go` con el nuevo mensaje.
2. Recompilo: `GOOS=linux GOARCH=amd64 go build -o goserver`.
3. Construyo: `docker build . -t tu-usuario/goserver:0.2.0`.
4. `docker run -p 8991:8991 tu-usuario/goserver:0.2.0` — pruebo la nueva versión.
5. `docker push tu-usuario/goserver:0.2.0` — subo la nueva versión.
6. `docker stop <ID> && docker rm <ID>` — limpio el contenedor.
7. `docker image rm tu-usuario/goserver:latest tu-usuario/goserver:0.2.0` — elimino las imágenes locales.
8. `docker pull tu-usuario/goserver:0.2.0` — descargo la nueva versión.
9. `docker run -p 8991:8991 tu-usuario/goserver:0.2.0` — ejecuto la versión descargada.
