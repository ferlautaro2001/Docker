## Tags y la convención de `latest`

El tag `latest` en Docker **no siempre es la versión más reciente**. Es simplemente el **tag predeterminado** que se usa cuando no se especifica ninguno. Si no le pongo un tag a una imagen, Docker le asigna `latest` automáticamente.

Por ejemplo:
- `docker build -t mi-app .` → tag `latest`
- `docker build -t mi-app:1.0.0 .` → tag `1.0.0`
- `docker push mi-app` → sube con tag `latest`

### ¿El tag `latest` siempre es la última versión?

**No necesariamente.** Si construyo una imagen y le pongo tag `latest`, y luego construyo otra versión sin actualizar el tag `latest`, esta última no apuntará a la versión más reciente.

**Ejemplo:**
```bash
# Versión 1.0.0 (también etiquetada como latest)
docker build -t mi-app:1.0.0 -t mi-app:latest .

# Versión 2.0.0 (sin actualizar latest)
docker build -t mi-app:2.0.0 .
docker push mi-app:2.0.0
```

En este caso, `latest` sigue apuntando a `1.0.0`, aunque `2.0.0` sea más nueva. Por eso, la convención recomendada es:

1. **Usar tags semánticos** para todas las versiones (`1.0.0`, `2.0.0`, etc.).
2. **Actualizar el tag `latest`** explícitamente cuando se publique una nueva versión.
3. **No confiar en `latest` para entornos de producción** — siempre usar un tag específico.

---

### Buenas prácticas

| Práctica | Recomendación |
|----------|---------------|
| Tags semánticos | Usar `1.0.0`, `2.1.3`, etc. |
| Tag `latest` | Actualizarlo en la versión más reciente |
| Producción | Siempre usar tags específicos (`mi-app:1.0.0`) |
| Desarrollo | Usar `latest` para la versión de desarrollo |

**Comando para etiquetar múltiples tags en una sola construcción:**
```bash
docker build -t mi-app:1.0.0 -t mi-app:latest .
```

**Comando para subir todos los tags:**
```bash
docker push mi-app --all-tags
```

---

### Ejemplo de pipeline de publicación

```bash
# 1. Construir la imagen con versión semántica y latest
VERSION="1.2.3"
docker build -t mi-app:$VERSION -t mi-app:latest .

# 2. Subir ambos tags
docker push mi-app:$VERSION
docker push mi-app:latest
```

> 🧠 **Conclusión:** `latest` es solo un tag más, no una garantía de que sea la versión más reciente. La mejor práctica es usar tags semánticos para versiones específicas y actualizar `latest` manualmente cuando corresponda.
