## `--cpus` y `--memory`

Cuando un contenedor consume demasiados recursos, puedo limitar su uso con flags de `docker run`. Esto es útil para:

- Evitar que un contenedor "devore" todos los recursos del host.
- Asegurar un reparto justo entre varios contenedores.
- Cumplir con límites de recursos en entornos de producción.

---

### 1. Ejecutar un contenedor con límite de CPU

```bash
docker run -d --cpus="0.25" --name cpu-stress alexeiled/stress-ng --cpu 2 --timeout 10m
```

**Salida esperada:**
```
2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f
```

> 📝 **Explicación:**
> - `--cpus="0.25"` — el contenedor solo puede usar el 25% de un núcleo de CPU.
> - `--cpu 2` — dentro del contenedor, `stress-ng` intenta usar 2 núcleos, pero Docker lo limita a 0.25.

---

### 2. Ver el uso de recursos en tiempo real

```bash
docker stats
```

**Salida esperada:**
```
CONTAINER ID   NAME         CPU %     MEM USAGE / LIMIT   MEM %     NET I/O          BLOCK I/O         PIDS
2f3a4b5c6d7e   cpu-stress   25.00%    2.5MiB / 7.78GiB    0.03%     0B / 0B          0B / 0B           2
```

> 📊 **Nota:** el uso de CPU está limitado al **25%** (0.25 núcleos), en lugar del 200% que tendría sin límite.

---

### 3. Comparación con y sin límite

| Situación | `--cpus` | Uso de CPU |
|-----------|----------|------------|
| Sin límite | (ninguno) | ~200% (2 núcleos) |
| Con límite | `--cpus="0.25"` | ~25% (0.25 núcleos) |

> 🧠 **Conclusión:** el flag `--cpus` limita el tiempo de CPU que el contenedor puede usar, independientemente de cuántos procesos o hilos intente ejecutar.

---

### 4. Limpiar el contenedor

```bash
docker stop cpu-stress
docker rm cpu-stress
```

**Salida esperada:**
```
cpu-stress
cpu-stress
```

---

### Otros flags de límite de recursos

| Flag | Descripción | Ejemplo |
|------|-------------|---------|
| `--cpus` | Límite de CPU (núcleos) | `--cpus="1.5"` (1.5 núcleos) |
| `--memory` | Límite de memoria (RAM) | `--memory="512m"` (512 MB) |
| `--memory-swap` | Límite de memoria + swap | `--memory-swap="1g"` |
| `--pids-limit` | Límite de procesos | `--pids-limit=100` |

**Ejemplo combinado:**
```bash
docker run -d --cpus="0.5" --memory="256m" --name myapp myimage
```

> 💡 **Nota:** estos límites son importantes en producción para garantizar que un contenedor no afecte a otros en el mismo host.

**Pasos para la lección (resumen):**
1. `docker run -d --cpus="0.25" --name cpu-stress alexeiled/stress-ng --cpu 2 --timeout 10m` — arranco contenedor con límite de CPU.
2. `docker stats` — veo el uso de CPU limitado al 25%.
3. `docker stop cpu-stress && docker rm cpu-stress` — limpio.
