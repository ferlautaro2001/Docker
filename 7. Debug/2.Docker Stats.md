## `docker stats`

`docker stats` me muestra el uso de recursos (CPU, memoria, red y E/S) de los contenedores en ejecución en tiempo real. Es como el `top` o `htop` del sistema, pero específico para contenedores Docker. Es útil para monitorear contenedores que consumen muchos recursos, o para detectar contenedores que se están saliendo de control.

---

### 1. Arrancar un contenedor que estresa la CPU

```bash
docker run -d --name cpu-stress alexeiled/stress-ng --cpu 2 --timeout 10m
```

**Salida esperada:**
```
2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f
```

> 📝 **Explicación:**
> - `alexeiled/stress-ng` — imagen que contiene la herramienta `stress-ng` para generar carga.
> - `--cpu 2` — usa 2 núcleos de CPU.
> - `--timeout 10m` — se detiene automáticamente después de 10 minutos (por si me olvido de detenerlo).

---

### 2. Arrancar un contenedor que usa memoria

```bash
docker run -d --name mem-stress alexeiled/stress-ng --vm 1 --vm-bytes 1G --timeout 10m
```

**Salida esperada:**
```
3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f3
```

> 📝 **Explicación:**
> - `--vm 1` — usa 1 proceso de memoria.
> - `--vm-bytes 1G` — asigna 1 GB de memoria.

---

### 3. Ver el uso de recursos en tiempo real

```bash
docker stats
```

**Salida esperada:**
```
CONTAINER ID   NAME         CPU %     MEM USAGE / LIMIT   MEM %     NET I/O          BLOCK I/O         PIDS
2f3a4b5c6d7e   cpu-stress   200.00%   2.5MiB / 7.78GiB    0.03%     0B / 0B          0B / 0B           2
3a4b5c6d7e8f   mem-stress   0.00%     1.0GiB / 7.78GiB    12.86%    0B / 0B          0B / 0B           2
```

> 📊 **Columnas:**
> - `CPU %` — porcentaje de CPU usado (puede superar el 100% si usa múltiples núcleos).
> - `MEM USAGE / LIMIT` — memoria usada vs límite total del contenedor (por defecto es el límite del host).
> - `MEM %` — porcentaje de memoria usada.
> - `NET I/O` — tráfico de red entrante/saliente.
> - `BLOCK I/O` — operaciones de lectura/escritura en disco.
> - `PIDS` — número de procesos dentro del contenedor.

---

### 4. Salir del modo stats

Presiono `Ctrl+C` para salir del modo `docker stats`.

---

### 5. Limpiar los contenedores

```bash
docker stop cpu-stress mem-stress
docker rm cpu-stress mem-stress
```

**Salida esperada:**
```
cpu-stress
mem-stress
cpu-stress
mem-stress
```

---

### Opciones útiles de `docker stats`

| Opción | Descripción |
|--------|-------------|
| `--no-stream` | Mostrar una sola vez (no refrescar) |
| `--format "table {{.Name}}\t{{.CPUPerc}}"` | Formato personalizado |
| `CONTAINER_ID` | Especificar uno o más contenedores específicos |

**Ejemplo de una sola vez:**
```bash
docker stats --no-stream
```

**Ejemplo con formato:**
```bash
docker stats --format "table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}"
```

---

### Casos de uso

- **Depuración** — encontrar qué contenedor está consumiendo muchos recursos.
- **Monitoreo** — observar el comportamiento de un contenedor en producción.
- **Planificación** — dimensionar recursos necesarios para un contenedor.
- **Detección temprana** — identificar fugas de memoria o procesos que se comen la CPU.

> 🧠 **Conclusión:** `docker stats` es la herramienta básica para monitorear el uso de recursos de los contenedores. Es indispensable para mantener la salud del sistema, especialmente en entornos con muchos contenedores.

**Pasos para la lección (resumen):**
1. `docker run -d --name cpu-stress alexeiled/stress-ng --cpu 2 --timeout 10m` — contenedor de estrés de CPU.
2. `docker run -d --name mem-stress alexeiled/stress-ng --vm 1 --vm-bytes 1G --timeout 10m` — contenedor de estrés de memoria.
3. `docker stats` — veo el uso de recursos en tiempo real.
4. `Ctrl+C` — salgo.
5. `docker stop cpu-stress mem-stress && docker rm cpu-stress mem-stress` — limpio.
