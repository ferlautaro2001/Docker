## `docker top`

`docker top` me muestra los **procesos en ejecución dentro de un contenedor**. Es como el comando `top` del sistema, pero específico para un contenedor. Muestra el PID dentro del contenedor, el usuario, el uso de CPU, el comando, etc. Es útil para inspeccionar qué procesos está ejecutando un contenedor.

---

### 1. Ver los procesos en el contenedor de CPU

```bash
docker top cpu-stress
```

**Salida esperada:**
```
UID                 PID                 PPID                C                   STIME               TTY                 TIME                CMD
root                12345               12344               150                 10:30               ?                   00:00:05            /usr/bin/stress-ng --cpu 2 --timeout 10m
root                12346               12345               150                 10:30               ?                   00:00:05            /usr/bin/stress-ng --cpu 2 --timeout 10m
```

> 📋 **Nota:** `C` es el uso de CPU (150% significa que está usando 1.5 núcleos). El contenedor `cpu-stress` tiene **2 procesos** de `stress-ng` (uno por cada núcleo solicitado).

---

### 2. Ver los procesos en el contenedor de memoria

```bash
docker top mem-stress
```

**Salida esperada:**
```
UID                 PID                 PPID                C                   STIME               TTY                 TIME                CMD
root                12347               12346               0                   10:31               ?                   00:00:00            /usr/bin/stress-ng --vm 1 --vm-bytes 1G --timeout 10m
root                12348               12347               0                   10:31               ?                   00:00:00            /usr/bin/stress-ng --vm 1 --vm-bytes 1G --timeout 10m
```

> 📋 **Nota:** el contenedor `mem-stress` tiene **2 procesos**: el principal y el que asigna memoria. El uso de CPU es 0% porque está esperando operaciones de memoria.

---

### 3. Diferencias clave

| Contenedor | Procesos | Uso de CPU | Uso de memoria |
|------------|----------|------------|----------------|
| `cpu-stress` | 2 procesos de `stress-ng` | Alto (~150%) | Bajo |
| `mem-stress` | 2 procesos de `stress-ng` | Bajo (~0%) | Alto (~1 GB) |

> 🧠 **Conclusión:** `docker top` me muestra los procesos dentro del contenedor, mientras que `docker stats` me muestra el uso de recursos del contenedor en su conjunto.

---

### 4. Limpiar los contenedores

```bash
docker stop cpu-stress mem-stress
docker rm cpu-stress mem-stress
```

**Salida esperada:**
```
cpu-stress
mem-stress
cpu-stress
mem-stress
```

---

### Comparación: `docker stats` vs `docker top`

| Comando | Qué muestra | Cuándo usarlo |
|---------|-------------|---------------|
| `docker stats` | Uso de recursos del contenedor (CPU, memoria, red, E/S) | Monitoreo general de recursos de contenedores |
| `docker top` | Procesos dentro del contenedor | Depuración específica de procesos internos |

> 💡 **Resumen:**
> - `docker stats` → **qué** está consumiendo recursos.
> - `docker top` → **quién** (qué procesos) está consumiendo esos recursos.

**Pasos para la lección (resumen):**
1. `docker top cpu-stress` — veo los procesos del contenedor CPU.
2. `docker top mem-stress` — veo los procesos del contenedor de memoria.
3. Comparo los resultados (CPU tiene 2 procesos con alto CPU, memoria tiene 2 procesos con alta memoria).
4. `docker stop cpu-stress mem-stress && docker rm cpu-stress mem-stress` — limpio.
