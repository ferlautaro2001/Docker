## `--network none` (contenedor aislado)

Voy a comprobar que el flag `--network none` realmente aísla el contenedor de la red exterior. Para eso, primero limpio el contenedor anterior y arranco uno nuevo sin red.

### Limpiar el contenedor anterior

```bash
docker ps
```

**Salida esperada:**
```
CONTAINER ID   IMAGE                           COMMAND                  CREATED         STATUS         PORTS                  NAMES
2f3a4b5c6d7e   docker/getting-started:latest   "/docker-entrypoint.…"   2 minutes ago   Up 2 minutes   0.0.0.0:8965->80/tcp   naughty_galileo
```

```bash
docker stop 2f3a4b5c6d7e
docker rm 2f3a4b5c6d7e
```

**Salida esperada:**
```
2f3a4b5c6d7e
2f3a4b5c6d7e
```

---

### Arrancar un nuevo contenedor sin red

```bash
docker run -d --network none docker/getting-started
```

**Salida esperada:**
```
3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f3
```

---

### Verificar que no tiene red

```bash
docker exec 3a4b5c6d7e8f ip addr
```

**Salida esperada:**
```
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever
```

> ⚠️ **Nota:** solo tiene loopback, sin interfaz de red `eth0`, sin IP, sin puerta de enlace, sin DNS.

---

### Intentar hacer ping a google.com

```bash
docker exec 3a4b5c6d7e8f ping google.com -W 2
```

**Salida esperada (el contenedor no tiene red):**
```
ping: google.com: Temporary failure in name resolution
```

> ❌ **Nota:** el contenedor no puede resolver el nombre de dominio porque no tiene DNS configurado.

---

### Si el contenedor tuviera red pero sin DNS

Si tuviera red pero no DNS, el error sería:

```
ping: google.com: Name or service not known
```

Y si tuviera red y DNS pero google.com no respondiera:

```
--- google.com ping statistics ---
2 packets transmitted, 0 received, 100% packet loss
```

Pero en este caso, ni siquiera tiene red, así que el error es de resolución de nombre (DNS falla porque no hay red).

> 🧠 **Conclusión:** el flag `--network none` aísla completamente el contenedor de la red exterior. No hay puertos expuestos, no hay comunicación con el host ni con otros contenedores, y ni siquiera puede resolver nombres de dominio.

---

### ¿Qué error vi en el ping?

El mensaje de error que vi en mi terminal fue:

```
ping: google.com: Temporary failure in name resolution
```

**Pasos para la lección (resumen):**
1. `docker ps` — veo los contenedores activos.
2. `docker stop <ID>` — detengo el contenedor getting-started.
3. `docker rm <ID>` — elimino el contenedor.
4. `docker run -d --network none docker/getting-started` — arranco un nuevo contenedor sin red.
5. `docker exec <ID> ping google.com -W 2` — intento hacer ping, falla.
