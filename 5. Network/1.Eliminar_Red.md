## `--network none`

El flag `--network none` en `docker run` aísla completamente un contenedor de la red exterior. El contenedor **no tiene interfaz de red** excepto la interfaz loopback (`127.0.0.1`). No puede:

- Comunicarse con otros contenedores.
- Acceder al host (ni viceversa).
- Salir a Internet.
- Recibir conexiones entrantes.

Esto es útil para:

- Ejecutar código de terceros no confiable.
- Aislar contenedores con virus sospechosos para auditoría.
- Evitar que un contenedor filtre datos sensibles por red.

---

### Ejemplo: contenedor sin red

```bash
docker run -d --network none nginx
```

**Salida esperada:**
```
2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f
```

---

### Verificar que no tiene red

```bash
docker exec 2f3a4b5c6d7e ip addr
```

**Salida esperada:**
```
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever
```

> ⚠️ **Nota:** solo tiene `lo` (loopback), sin interfaz `eth0`. No hay IP asignada, ni puerta de enlace, ni DNS.

---

### Intentar hacer ping a Google (fallará)

```bash
docker exec 2f3a4b5c6d7e ping google.com
```

**Salida esperada (no hay red):**
```
ping: google.com: Temporary failure in name resolution
```

---

### Intentar acceder a la página desde el navegador (fallará)

```bash
docker run -d --network none -p 8080:80 nginx
```

**Salida esperada:**
```
docker: Error response from daemon: driver failed programming external connectivity on endpoint ...
```

> ❌ **Nota:** ni siquiera se puede mapear puertos (`-p`) porque el contenedor no tiene red.

---

### ¿Cómo identifico un contenedor sin red?

```bash
docker ps
```

```
CONTAINER ID   IMAGE   COMMAND                  CREATED         STATUS         PORTS     NAMES
2f3a4b5c6d7e   nginx   "/docker-entrypoint.…"   5 seconds ago   Up 4 seconds             boring_shockley
```

> 📋 **Nota:** la columna `PORTS` estará vacía porque no hay red configurada.

---

### Casos de uso reales

| Escenario | Por qué usar `--network none` |
|-----------|-------------------------------|
| Código de terceros no confiable | Evita que el contenedor envíe datos a servidores externos. |
| Sandbox de código en plataformas educativas | Los estudiantes ejecutan código aislado sin acceso a red. |
| Auditoría de malware | Aisla un contenedor sospechoso para analizarlo sin riesgos. |
| Procesamiento de datos sensibles | Elimina el riesgo de exfiltración de datos por red. |


**Pasos para la lección (resumen):**
1. `docker run -d --network none nginx` — arranco contenedor sin red.
2. `docker exec <ID> ip addr` — verifico que solo tiene loopback.
3. No puedo hacer `ping` ni mapear puertos.
