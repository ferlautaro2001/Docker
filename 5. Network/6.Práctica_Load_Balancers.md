## Configurando el balanceador de carga

Ahora que tengo dos servidores de aplicación (Caddy) corriendo en la red `caddytest`, voy a agregar un **balanceador de carga** que distribuya el tráfico entre ambos usando la estrategia *round-robin*.

### 1. Limpiar contenedores residuales

```bash
docker ps -a
```

**Salida esperada:**
```
CONTAINER ID   IMAGE                           COMMAND                  CREATED         STATUS         PORTS                  NAMES
2f3a4b5c6d7e   caddy                           "caddy run --config …"   5 minutes ago   Up 5 minutes                           caddy1
3a4b5c6d7e8f   caddy                           "caddy run --config …"   5 minutes ago   Up 5 minutes                           caddy2
4a5b6c7d8e9f   docker/getting-started          "/docker-entrypoint.…"   2 minutes ago   Exited (0) 1 minute ago                hopeful_ride
```

```bash
docker stop 4a5b6c7d8e9f
docker rm 4a5b6c7d8e9f
```

**Salida esperada:**
```
4a5b6c7d8e9f
4a5b6c7d8e9f
```

---

### 2. Crear el archivo `Caddyfile`

En mi directorio de trabajo creo un archivo llamado `Caddyfile` con el siguiente contenido:

```
localhost:80

reverse_proxy caddy1:80 caddy2:80 {
	lb_policy       round_robin
}
```

> 📝 **¿Qué hace cada línea?**
> - `localhost:80` — Caddy escuchará en el puerto 80 dentro del contenedor.
> - `reverse_proxy caddy1:80 caddy2:80` — reenvía el tráfico a estos dos servidores.
> - `lb_policy round_robin` — usa la estrategia round-robin para distribuir las peticiones.

> 💡 **Nota:** `caddy1` y `caddy2` se resuelven automáticamente gracias a que el balanceador estará en la misma red `caddytest` (resolución DNS de Docker).

---

### 3. Levantar el balanceador de carga

```bash
docker run -d --network caddytest -p 8880:80 -v $PWD/Caddyfile:/etc/caddy/Caddyfile caddy
```

**Salida esperada:**
```
4a5b6c7d8e9f0a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4
```

- `--network caddytest` — conecta el balanceador a la misma red que los servidores.
- `-p 8880:80` — expone el puerto 80 del balanceador al puerto 8880 del host.
- `-v $PWD/Caddyfile:/etc/caddy/Caddyfile` — monta mi archivo de configuración en la ruta donde Caddy lo espera.

### 5. Probar el balanceador (varias veces)

```bash
curl http://localhost:8880/
```

**Salida esperada (primera petición):**
```html
<html>
  <body>
    <h1>Hello from server 1</h1>
  </body>
</html>
```

**Salida esperada (segunda petición):**
```html
<html>
  <body>
    <h1>Hello from server 2</h1>
  </body>
</html>
```

**Salida esperada (tercera petición):**
```html
<html>
  <body>
    <h1>Hello from server 1</h1>
  </body>
</html>
```

> 📊 **Conclusión:** cada `curl` va alternando entre `server 1` y `server 2` gracias a la política `round_robin`.

---

### 6. Probar en el navegador

Abro `http://localhost:8880/` en mi navegador. Si el navegador no está cacheando, cada vez que refresco debería alternar entre "Hello from server 1" y "Hello from server 2".

> ⚠️ **Nota:** algunos navegadores cachean las respuestas HTML. Si no veo el cambio al refrescar, uso `curl` para comprobar que el balanceador funciona.

---

### 7. Verificar la arquitectura

```
               ┌─────────────┐
Host ──────────►  :8880      │  (balanceador expuesto al host)
               │  (Caddy LB) │
               └──────┬──────┘
                      │
               ┌──────┴──────┐
               │  caddytest  │  (red personalizada)
               │   (bridge)  │
               └──────┬──────┘
                      │
        ┌─────────────┴─────────────┐
        │                           │
 ┌──────▼──────┐           ┌────────▼──────┐
 │  caddy1:80  │           │   caddy2:80   │  (servidores de aplicación
 │  (server1)  │           │   (server2)   │   ocultos)
 └─────────────┘           └───────────────┘
```

> 🧠 **Conclusión:** el balanceador de carga es el único punto de entrada público, y distribuye el tráfico entre los servidores de aplicación en la red interna.

**Pasos para la lección (resumen):**
1. Limpio contenedores que no sean `caddy1` y `caddy2`.
2. Creo `Caddyfile` con la configuración del balanceador.
3. `docker run -d --network caddytest -p 8880:80 -v $PWD/Caddyfile:/etc/caddy/Caddyfile caddy` — arranco el balanceador.
4. `curl http://localhost:8880/` — veo la respuesta (alterna entre server1 y server2).
