
## Load Balancers

Un **balanceador de carga** (*load balancer*) es un servidor que distribuye el tráfico de red entre múltiples servidores backend. Es la base de la arquitectura escalable: en lugar de que un solo servidor maneje todas las peticiones, el balanceador reparte el trabajo entre varios.

### ¿Por qué usar un balanceador de carga?

- **Escalabilidad horizontal** — puedo agregar más servidores backend para manejar más tráfico.
- **Alta disponibilidad** — si un servidor falla, el balanceador deja de enviarle tráfico.
- **Distribución de carga** — evita que un solo servidor se sature.

### Algoritmos comunes

| Algoritmo | Cómo funciona |
|-----------|---------------|
| **Round Robin** | Distribuye las peticiones de forma cíclica: petición 1 → Servidor 1, petición 2 → Servidor 2, etc. |
| **Least Connections** | Envía nuevas peticiones al servidor con menos conexiones activas. |
| **IP Hash** | Usa el hash de la IP del cliente para siempre enviar al mismo servidor (útil para sesiones). |
| **Weighted** | Asigna pesos a los servidores: los más potentes reciben más tráfico. |

### Ejemplo: Round Robin con 3 servidores

```
Petición 1 → Servidor 1
Petición 2 → Servidor 2
Petición 3 → Servidor 3
Petición 4 → Servidor 1
Petición 5 → Servidor 2
Petición 6 → Servidor 3
```

### ¿Cómo se relaciona con Docker?

En Docker, los balanceadores de carga suelen implementarse de dos formas:

1. **Usando un proxy reverso** como Nginx o HAProxy dentro de un contenedor.
2. **Usando el balanceador integrado de Docker Swarm** o de Kubernetes.

### Ejemplo básico con Nginx

Un archivo de configuración de Nginx para balancear entre 3 contenedores:

```nginx
upstream backend {
    server web1:80;
    server web2:80;
    server web3:80;
}

server {
    listen 80;
    location / {
        proxy_pass http://backend;
    }
}
```

### En producción (en la nube)

Los proveedores de nube ofrecen balanceadores de carga como servicio:

- **AWS ELB** (Elastic Load Balancer)
- **GCP Cloud Load Balancing**
- **Azure Load Balancer**

Estos pueden balancear tráfico entre máquinas virtuales, contenedores o incluso regiones geográficas completas.

### Conclusión

El balanceador de carga es el **punto de entrada** del tráfico a la aplicación. Es quien decide a qué servidor va cada petición, permitiendo que la aplicación crezca horizontalmente y sea tolerante a fallos. En el ecosistema de Docker y contenedores, es una pieza fundamental para arquitecturas escalables y resilientes.
