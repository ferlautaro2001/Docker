## Redes personalizadas en Docker

Docker me permite crear **redes personalizadas** para aislar contenedores entre sí o para que se comuniquen solo dentro de esa red. En esta lección voy a crear una red llamada `caddytest` donde los servidores de aplicación (Caddy) estarán ocultos, y solo el balanceador de carga estará expuesto al host.

### 1. Crear una red personalizada

```bash
docker network create caddytest
```

**Salida esperada:**
```
caddytest
```

---

### 2. Ver las redes disponibles

```bash
docker network ls
```

**Salida esperada:**
```
NETWORK ID     NAME         DRIVER    SCOPE
2f3a4b5c6d7e   bridge       bridge    local
8a9b0c1d2e3f   caddytest    bridge    local
4a5b6c7d8e9f   host         host      local
0a1b2c3d4e5f   none         null      local
```

> 📋 **Nota:** veo que `caddytest` apareció como una red de tipo `bridge` (el driver por defecto).

---

### 3. Detener y eliminar los contenedores anteriores

```bash
docker stop 2f3a4b5c6d7e 3a4b5c6d7e8f
docker rm 2f3a4b5c6d7e 3a4b5c6d7e8f
```

**Salida esperada:**
```
2f3a4b5c6d7e
3a4b5c6d7e8f
```

---

### 4. Levantar los servidores Caddy en la red personalizada

**Servidor 1 (sin exponer puerto):**
```bash
docker run -d --name caddy1 --network caddytest -v $PWD/index1.html:/usr/share/caddy/index.html caddy
```

**Salida esperada:**
```
2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f
```

**Servidor 2 (sin exponer puerto):**
```bash
docker run -d --name caddy2 --network caddytest -v $PWD/index2.html:/usr/share/caddy/index.html caddy
```

**Salida esperada:**
```
3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f3
```

> ⚠️ **Importante:** no uso `-p` para exponer puertos. Estos contenedores **no son accesibles desde el host**, solo desde la red `caddytest`.

---

### 5. Verificar que los contenedores están en la red

```bash
docker ps
```

**Salida esperada:**
```
CONTAINER ID   IMAGE     COMMAND                  CREATED         STATUS         PORTS     NAMES
2f3a4b5c6d7e   caddy     "caddy run --config …"   5 seconds ago   Up 4 seconds             caddy1
3a4b5c6d7e8f   caddy     "caddy run --config …"   4 seconds ago   Up 3 seconds             caddy2
```

> 📋 **Nota:** la columna `PORTS` está vacía, confirmando que no están expuestos al host.

---

### 6. Levantar un contenedor de prueba en la misma red

```bash
docker run -it --network caddytest docker/getting-started /bin/sh
```

**Salida esperada:** el prompt cambia a `#`, indicando que estoy dentro del contenedor.

---

### 7. Probar la resolución de nombres DNS

Dentro del contenedor `getting-started`, hago curl a los servidores por su nombre (resolución DNS automática):

```bash
# curl caddy1
```

**Salida esperada (debería mostrar el HTML del servidor 1):**
```html
<html>
  <body>
    <h1>Hello from server 1</h1>
  </body>
</html>
```

```bash
# curl caddy2
```

**Salida esperada (debería mostrar el HTML del servidor 2):**
```html
<html>
  <body>
    <h1>Hello from server 2</h1>
  </body>
</html>
```

> 🧠 **¿Cómo funciona?** Docker tiene un servidor DNS interno en la red `caddytest`. Cuando pido `curl caddy1`, Docker resuelve el nombre `caddy1` a la IP del contenedor con ese nombre (gracias al flag `--name` que usé al crearlo).

---

### 8. Salir de la shell del contenedor

```bash
# exit
```

**Salida esperada:** vuelvo al prompt de mi terminal host.

**Pasos para la lección (resumen):**
1. `docker network create caddytest` — creo la red personalizada.
2. `docker network ls` — verifico que existe.
3. `docker stop` y `docker rm` los contenedores Caddy anteriores.
4. `docker run -d --name caddy1 --network caddytest -v $PWD/index1.html:/usr/share/caddy/index.html caddy` — arranco caddy1 sin exponer puertos.
5. `docker run -d --name caddy2 --network caddytest -v $PWD/index2.html:/usr/share/caddy/index.html caddy` — arranco caddy2 sin exponer puertos.
6. `docker run -it --network caddytest docker/getting-started /bin/sh` — abro una shell en la red.
7. `curl caddy1` y `curl caddy2` — pruebo la resolución DNS.
8. `exit` — salgo del contenedor.
