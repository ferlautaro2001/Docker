## Dockerizando Python con Debian (y un error esperado)

En esta lección voy a intentar correr el script Python sobre una imagen base Debian **sin** el intérprete de Python instalado. Esto provocará un error, demostrando que las imágenes base deben incluir las dependencias necesarias para el lenguaje.

---

### 1. Crear el `Dockerfile.py`

En mi directorio de trabajo creo un archivo `Dockerfile.py`:

```dockerfile
FROM debian:stable-slim
COPY main.py main.py
COPY books/ books/
CMD ["python", "main.py"]
```

> 📝 **¿Qué hace?**
> - `FROM debian:stable-slim` — usa Debian como imagen base.
> - Copia `main.py` y la carpeta `books/` al contenedor.
> - `CMD ["python", "main.py"]` — intenta ejecutar el script con `python`.

---

### 2. Construir la imagen

```bash
docker build -t bookbot -f Dockerfile.py .
```

**Salida esperada:**

> 📦 **Nota:** la imagen se construyó sin errores, pero eso no significa que funcione.

---

### 3. Ejecutar el contenedor

```bash
docker run bookbot
```

**Salida esperada (error):**
```
docker: Error response from daemon: failed to create task for container: failed to create shim task: OCI runtime create failed: runc create failed: unable to start container process: exec: "python": executable file not found in $PATH: unknown.
```

> ❌ **¿Por qué falla?**
> - La imagen `debian:stable-slim` no tiene Python instalado.
> - Cuando el contenedor intenta ejecutar `python main.py`, no encuentra el intérprete en el `$PATH`.

---

### 4. Verificar el error

```bash
docker ps -a
```

**Salida esperada:**
```
CONTAINER ID   IMAGE      COMMAND              CREATED         STATUS                     PORTS     NAMES
3f4a5b6c7d8e   bookbot    "python main.py"     2 seconds ago   Exited (127) 1 second ago             sad_banach
```

> 📋 **Nota:** `STATUS` muestra `Exited (127)`, que es el código de error estándar cuando un comando no se encuentra.

---

### ¿Por qué falla?

| Componente | Presente en Debian slim | Necesario para Python |
|------------|------------------------|-----------------------|
| Debian OS  | ✅ Sí                  | ✅ Sí                 |
| Python     | ❌ No                  | ✅ Sí                 |
| Script     | ✅ Sí                  | ✅ Sí                 |
| Libro      | ✅ Sí                  | ✅ Sí                 |

> 🧠 **Conclusión:** no basta con copiar el código. El contenedor necesita el **intérprete de Python** instalado para ejecutar el script. Por eso se usa `FROM python:3.10-slim` en lugar de `FROM debian:stable-slim` para imágenes Python.

---

### Solución para este problema

Para que funcione, el `Dockerfile` debería usar una imagen base que ya incluya Python, o instalar Python en la imagen Debian:

**Opción 1 (recomendada):**
```dockerfile
FROM python:3.10-slim
COPY main.py main.py
COPY books/ books/
CMD ["python", "main.py"]
```

**Opción 2 (manual):**
```dockerfile
FROM debian:stable-slim
RUN apt-get update && apt-get install -y python3
COPY main.py main.py
COPY books/ books/
CMD ["python3", "main.py"]
```

Pero para esta lección, el error es esperado y forma parte del aprendizaje.

**Pasos para la lección (resumen):**
1. Creo `Dockerfile.py` con `FROM debian:stable-slim`, copio `main.py` y `books/`, y `CMD ["python", "main.py"]`.
2. `docker build -t bookbot -f Dockerfile.py .` — construyo la imagen.
3. `docker run bookbot` — ejecuto el contenedor y veo el error `exec: "python": executable file not found in $PATH`.
