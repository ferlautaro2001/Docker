
## `docker stop` y `docker kill`

Estos dos comandos detienen contenedores en ejecución, pero con diferencias clave:

- **`docker stop`** es la forma **ordenada** y preferida. Envía una señal `SIGTERM` al proceso principal del contenedor, dándole tiempo para cerrar conexiones, guardar datos y finalizar correctamente. Si después de 10 segundos (por defecto) no termina, Docker lo mata con `SIGKILL` igual.
- **`docker kill`** es la forma **brutal** y forzada. Envía `SIGKILL` directamente, lo que mata el proceso de inmediato sin posibilidad de limpieza. Solo lo uso si `docker stop` no responde.

Primero necesito el ID del contenedor que quiero detener, lo obtengo con `docker ps`.

**Ejemplo para obtener el ID:**
```bash
docker ps
```

**Salida esperada:**
```
CONTAINER ID   IMAGE                           COMMAND                  CREATED         STATUS         PORTS                  NAMES
2f3a4b5c6d7e   docker/getting-started:latest   "/docker-entrypoint.…"   5 minutes ago   Up 5 minutes   0.0.0.0:8965->80/tcp   naughty_galileo
```

**Ejemplo de `docker stop` (reemplazar con mi ID real):**
```bash
docker stop 2f3a4b5c6d7e
```

**Salida esperada (devuelve el ID del contenedor que detuve):**
```
2f3a4b5c6d7e
```

**Ejemplo de `docker kill` (si `stop` no funciona):**
```bash
docker kill 2f3a4b5c6d7e
```

**Salida esperada (devuelve el ID del contenedor que maté):**
```
2f3a4b5c6d7e
```

> ⚠️ **Nota:** después de detener el contenedor, si refresco `http://localhost:8965` ya no debería ver la página web porque el servidor dentro del contenedor ya no está corriendo.

---

### Verificación final

Para confirmar que el contenedor ya no está corriendo, vuelvo a ejecutar `docker ps`. Si no aparece en la lista, significa que se detuvo correctamente.

```bash
docker ps
```

**Salida esperada (ya no debería aparecer el contenedor de getting-started):**
```
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES
(no hay contenedores en ejecución o solo otros que no son el que detuve)
```


**Pasos para la lección (resumen):**
1. `docker ps` — obtengo el ID del contenedor.
2. `docker stop <ID>` — detengo el contenedor de forma ordenada.
3. Refresco `http://localhost:8965` — ya no debería funcionar.
