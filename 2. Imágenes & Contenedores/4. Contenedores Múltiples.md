
## Múltiples contenedores

Acá levanté **cinco contenedores distintos** a partir de la misma imagen `docker/getting-started`, pero cada uno escuchando en un puerto diferente de mi máquina host (del 8965 al 8969). El puerto interno siempre es el 80, pero lo mapeo a distintos puertos externos para evitar conflictos, ya que dos procesos no pueden ocupar el mismo puerto en el host.

Como cada contenedor es una instancia aislada, aunque todos usen la misma imagen, cada uno tiene su propio sistema de archivos, su propia red y sus propios procesos. Son completamente independientes entre sí.

### Crear los contenedores

**Ejemplo de comandos:**
```bash
docker run -d -p 8965:80 docker/getting-started
docker run -d -p 8966:80 docker/getting-started
docker run -d -p 8967:80 docker/getting-started
docker run -d -p 8968:80 docker/getting-started
docker run -d -p 8969:80 docker/getting-started
```

## `docker ps` (para ver todos)

`docker ps` me muestra todos los contenedores activos y sus puertos mapeados. En la columna `PORTS` veo que cada contenedor tiene su propio puerto en el host, todos apuntando al puerto 80 interno.

**Ejemplo de comando:**
```bash
docker ps
```

### Detener los contenedores (al finalizar)

Cuando termine los tests, detengo todos los contenedores:

```bash
docker stop 2f3a4b5c6d7e 3a4b5c6d7e8f 4a5b6c7d8e9f 5a6b7c8d9e0f 6a7b8c9d0e1f
```

O usando el comando `docker stop $(docker ps -q)` para detener todos los contenedores en ejecución de una vez.

> 💡 **Tip:** `docker ps -q` devuelve solo los IDs, y `$()` ejecuta ese comando y pasa los IDs como argumentos a `docker stop`.

1. Ejecuto los 5 comandos `docker run -d -p 8965:80 docker/getting-started` hasta `-p 8969:80`.

3. Abro cada URL en el navegador para confirmar que funcionan.
4. Al terminar los tests, detengo los contenedores para no dejar recursos ocupados.
