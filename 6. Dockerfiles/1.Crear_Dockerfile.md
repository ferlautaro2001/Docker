## Dockerfiles

Hasta ahora usé imágenes que otras personas crearon (como `nginx`, `caddy`, `ghost`). Pero Docker también me permite **crear mis propias imágenes** usando un archivo llamado `Dockerfile`. Este archivo contiene las instrucciones para construir una imagen, paso a paso.

El `Dockerfile` es la definición de cómo se debe construir la imagen, y al tenerlo en control de versiones, puedo reproducir el mismo entorno en cualquier máquina. Es una forma de "infraestructura como código" (IaC).

---

### 1. Crear un `Dockerfile`

En mi directorio de trabajo creo un archivo llamado `Dockerfile` (sin extensión) con el siguiente contenido:

```dockerfile
# This is a comment

# Use a lightweight debian os
# as the base image
FROM debian:stable-slim

# execute the 'echo "hello world"'
# command when the container runs
CMD ["echo", "hello world"]
```

> 📝 **¿Qué significa cada línea?**
> - `FROM debian:stable-slim` — indica la imagen base que voy a usar (Debian en su versión estable y liviana).
> - `CMD ["echo", "hello world"]` — define qué comando se ejecuta cuando el contenedor arranca, en formato JSON (el comando a ejecutar y sus argumentos).

> 💡 **Comentarios:** las líneas que comienzan con `#` son comentarios.

---

### 2. Construir la imagen

```bash
docker build . -t helloworld:latest
```

**Salida esperada:**
```
[+] Building 0.2s (6/6) FINISHED
 => [internal] load build definition from Dockerfile
 => => transferring dockerfile: 188B
 => [internal] load .dockerignore
 => => transferring context: 2B
 => [1/1] FROM docker.io/library/debian:stable-slim
 => CACHED [1/1] FROM docker.io/library/debian:stable-slim
 => exporting to image
 => => exporting layers
 => => writing image sha256:2f3a4b5c6d7e...
 => => naming to docker.io/library/helloworld:latest
```

- `.` — el contexto de construcción (directorio actual).
- `-t helloworld:latest` — nombra la imagen como `helloworld` y le asigna la etiqueta `latest`.

---

### 3. Verificar que la imagen se creó

```bash
docker images
```

**Salida esperada (debería incluir `helloworld`):**
```
REPOSITORY    TAG       IMAGE ID       CREATED              SIZE
helloworld    latest    2f3a4b5c6d7e   About a minute ago   55.3MB
debian        stable-slim  8a9b0c1d2e3f   2 weeks ago          55.3MB
```

---

### 4. Ejecutar un contenedor con mi nueva imagen

```bash
docker run helloworld
```

**Salida esperada:**
```
hello world
```

> 🚀 **¡Funciona!** El contenedor arrancó, ejecutó el comando `echo "hello world"` y terminó.

---

### 5. Verificar que el contenedor se detuvo

```bash
docker ps
```

**Salida esperada:**
```
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES
```

> 📋 **Nota:** no aparece ningún contenedor porque `echo` es un comando que termina inmediatamente. El contenedor se detiene cuando el comando principal finaliza.

---

### 6. Ver los contenedores detenidos

```bash
docker ps -a
```

**Salida esperada:**
```
CONTAINER ID   IMAGE         COMMAND                  CREATED         STATUS                      PORTS     NAMES
7a8b9c0d1e2f   helloworld    "echo 'hello world'"     5 seconds ago   Exited (0) 3 seconds ago              friendly_galileo
```

> 📋 **Nota:** `STATUS` muestra `Exited (0)`, indicando que el contenedor terminó correctamente (código de salida 0).

---

### 7. Limpiar el archivo Dockerfile

```bash
rm Dockerfile
```

> 🗑️ **Nota:** la imagen `helloworld` sigue existiendo, aunque haya borrado el `Dockerfile`. El `Dockerfile` solo se necesita para construir la imagen, no para ejecutarla.

---

### ¿Para qué sirve un `Dockerfile` en el mundo real?

- **Inmutable** — definición de la imagen (que es reproducible).
- **Control de versiones** — se puede trackear en Git.
- **CI/CD** — los pipelines pueden construir imágenes automáticamente.
- **Portabilidad** — mismo entorno en local, staging y producción.

> 🧠 **Conclusión:** el `Dockerfile` me permite definir mi aplicación como código y crear imágenes personalizadas que puedo distribuir y ejecutar en cualquier entorno que tenga Docker.

**Pasos para la lección (resumen):**
1. Creo `Dockerfile` con `FROM debian:stable-slim` y `CMD ["echo", "hello world"]`.
2. `docker build . -t helloworld:latest` — construyo la imagen.
3. `docker run helloworld` — ejecuto el contenedor y veo "hello world".
4. `docker ps` — veo que el contenedor ya se detuvo (comando terminó).
5. `docker ps -a` — veo el contenedor en estado `Exited`.
6. `rm Dockerfile` — elimino el archivo (la imagen ya está construida).
